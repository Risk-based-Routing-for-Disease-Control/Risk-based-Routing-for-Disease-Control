# ML

`감염농장_전처리.ipynb`가 만든 시/도별 농장현황·감염농장(`data/{시/도}/농장현황/`, `data/{시/도}/감염농장/`)에서, 발생일 기준 시간 윈도우의 농장현황만 추출해 ML 학습용 데이터셋을 만드는 폴더. **감염농장과 조인하지 않고 농장현황만 추출**하며, 출력에는 라벨이 없다.

`조사날짜`는 원본 농장현황의 조사날짜를 그대로 유지한다. 대신 ML 학습의 기준 시점(base date)을 감염날짜에 맞추기 위해 **`감염날짜`** 컬럼을 새로 만든다: 농장현황 좌표 반경 10km 이내 감염농장의 `outbreak_date`(원래 조사날짜와 시간상 가장 가까운 것, 동률이면 공간 거리가 더 가까운 것) 또는 그것도 없으면 해당 윈도우의 감염 발생일(occr_date)로 채운 값이다. 자세한 기준은 아래 2번 섹션 참고.

## 실행 순서

```
1. ML_농장현황_전처리.ipynb  (PROVINCE·WINDOW 변수만 바꿔 시/도·윈도우별 반복 실행)
   -> ML_{PROVINCE}_농장현황_{WINDOW}.csv             (감염날짜 컬럼을 채운 뒤 1건만 남김)
   -> ML_{PROVINCE}_농장현황_{WINDOW}_alldates.csv    (조사날짜·감염날짜가 다른 행은 보존, 완전 중복만 제거)
   -> ML_농장현황_건수_{WINDOW}.csv / _{WINDOW}_alldates.csv (시/도별 건수 누적)
2. ML_merge_전국.py
   -> ML_전국_농장현황_6months.csv / _6months_alldates.csv
   -> ML_전국_농장현황_1year.csv / _1year_alldates.csv
```

`감염농장_전처리.ipynb`를 먼저 같은 `PROVINCE`로 실행해 `data/{PROVINCE}/농장현황/`, `data/{PROVINCE}/감염농장/`을 만들어둬야 한다.

## ML_농장현황_전처리.ipynb -> ML_{PROVINCE}_농장현황_{WINDOW}.csv

`WINDOW`는 `"6months"`(±6개월) 또는 `"1year"`(±1년) 중 하나를 고른다.

1. **시간 윈도우 추출**: 그 시군에 감염농장이 발생한 날짜(occr_date)마다, 그 발생일 기준 ±WINDOW 범위의 농장현황 행만 모은다 (원본 조사날짜로 필터링). 이 `조사날짜`는 이후 단계에서도 바뀌지 않고 원본 그대로 남는다.
2. **좌표 결측치 보완**: 경기도를 제외한 시/도는 원본 농장현황에 `WGS84위도`/`WGS84경도`가 없다. 다음 단계의 반경 매칭이 좌표에 의존하므로, `scripts/geocode_cache.json`(주소를 읍/면/동·리 단위로 잘라 Kakao로 미리 조회해둔 캐시)에서 같은 동/리의 좌표를 찾아 채운다. 캐시에 없는 주소는 그대로 비워두고(아래 반경 매칭이 실패해 occr_date로 대체됨), 새로 Kakao API를 호출하지는 않는다.
   - 같은 동/리에 속한 여러 농장은 정밀 주소가 달라도 캐시에 등록된 동일한 좌표를 공유한다 (동/리 단위 근사 지오코딩이라 정밀도가 낮음). 따라서 좌표가 없던 농장의 "반경 10km"는 실제로는 그 동/리 중심 기준이다.
3. **`감염날짜` 컬럼 채우기**: ML 학습의 기준 시점(base date)을 감염날짜에 맞추기 위해, 윈도우에 포함된 각 행마다 새 컬럼 `감염날짜`를 다음 기준으로 채운다.
   - 그 농장현황 좌표 반경 `RADIUS_KM`(10km, 시군 경계와 무관하게 전국 감염농장 기준) 이내에 있는 `최종감염농장/전국_최종감염농장.csv`의 감염농장들 중, 원래 조사날짜와 시간상 가장 가까운 `outbreak_date`를 찾아 그 값(연-월-일까지)을 채운다. 시간 거리가 같은 후보가 여러 개면(동률) 공간 거리(km)가 더 가까운 쪽을 우선한다.
   - 반경 안에 감염농장이 하나도 없으면, 그 행을 이 윈도우에 포함시킨 원인인 그 시군의 occr_date를 대신 채운다.
   - 시군명·농장명·주소·좌표가 정확히 같은 감염농장만 찾는 정확매칭이 아니라, 좌표 거리 기준 반경 검색이다 — 농장현황 좌표 주변에 다른 농장이 감염됐어도(자기 자신이 감염농장이 아니어도) 그 영향을 반영한다.
   - 구현은 `df.groupby(...).apply(lambda g: g)` 형태가 아니라 거리 컬럼으로 정렬 후 `drop_duplicates(keep="first")` 방식이다. pandas가 groupby+apply에서 그룹 키 컬럼을 결과에서 제외해버리는 동작이 있어서 우회했다.
4. **윈도우 간 중복 제거**: 감염농장이 여러 건이면 같은 농장이 서로 다른 occr_date 윈도우에 걸쳐 잡혀, 채워지는 감염날짜가 윈도우마다 달라질 수 있다 (반경 밖이면 occr_date 자체가 다르므로). 시군명·농장명·상세구분·소재지지번주소·위도·경도·사육두수가 같으면 같은 농장인데, 처리 방식이 다른 두 버전을 같이 만든다.
   - **`ML_{PROVINCE}_농장현황_{WINDOW}.csv`**: 같은 농장에 감염날짜가 여러 개면, 원래 조사날짜와 가장 가까운 것 1건만 남긴다.
   - **`ML_{PROVINCE}_농장현황_{WINDOW}_alldates.csv`**: 조사날짜·감염날짜가 다르면 버리지 않고 전부 남긴다 (둘 다 완전히 같은 행만 중복으로 제거). 반경 밖이라 occr_date로 대체되는 농장(주로 좌표가 없는 농장)일수록 윈도우마다 값이 달라지기 쉬워서, 일반 버전보다 행 수가 더 많다.
5. **닭/오리 세부분류 정규화**: 시/도마다 `축종명`/`상세구분`에 세부 항목(육계·종계·산란오리 등)이 들어가는 위치가 달라서, 루트 `livestock_codes.csv` 어휘 기준으로 닭/오리 관련 단어를 찾아 `축종명`을 닭/오리로, `상세구분`을 표준 세부값으로 통일한다.
   - 한 행에 표준 세부값이 두 개 들어있으면(예: 종계+산란계) 임의로 하나를 버리지 않고 `/`로 합쳐서 보존.
   - 닭/오리가 섞였거나 닭·오리가 아닌 축종과 섞인 행은 원본 데이터 자체의 모순이라 보고 원본 값을 그대로 둔다.
6. **컬럼 통일**: `시군명, 농장명, 축종명, 상세구분, 사육두수(마리), 소재지지번주소, WGS84위도, WGS84경도, 조사날짜, 감염날짜` 10개로 고정 (경기도에만 있는 소재지우편번호/소재지도로명주소/데이터기준일자/비고는 제외).
7. **저장**: `ML_{PROVINCE}_농장현황_{WINDOW}.csv`로 저장하고, `ML_농장현황_건수_{WINDOW}.csv`에 해당 시/도 건수를 갱신(다른 시/도 행은 유지).

## ML_merge_전국.py -> ML_전국_농장현황_6months.csv / ML_전국_농장현황_1year.csv

`ML_*_농장현황_6months.csv`, `ML_*_농장현황_1year.csv` 파일들을 윈도우별로 각각 모아 10개 표준 컬럼만 골라 맨 앞에 `시도명` 컬럼을 붙여 합친다. 시/도별 노트북을 새로 돌릴 때마다 다시 실행해서 기존 파일을 덮어써야 한다.

이 출력은 `KMA/match_farm_weather.py`가 농장별 날씨를 붙이는 입력으로 쓰인다 (`KMA/README.md` 참고).

## 윈도우 크기가 다른 두 버전

ML 학습용으로 윈도우 크기가 다른 두 데이터셋을 같이 보관한다.

- `ML_{시/도}_농장현황_6months.csv` / `ML_전국_농장현황_6months.csv`: 발생일 기준 **±6개월** 윈도우
- `ML_{시/도}_농장현황_1year.csv` / `ML_전국_농장현황_1year.csv`: 발생일 기준 **±1년** 윈도우

둘 다 같은 노트북(`ML_농장현황_전처리.ipynb`)에서 `WINDOW` 변수만 바꿔 생성한다.
