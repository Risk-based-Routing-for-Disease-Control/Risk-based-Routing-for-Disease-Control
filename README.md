# Risk-based-Routing-for-Disease-Control

## 감염농장 전처리 파이프라인

가축질병 발생정보(감염농장)와 가금류 농장현황(농장현황) 데이터를 매칭해서 감염농장의 시군명·축종·상세구분·사육두수·좌표를 보완하는 파이프라인. 코드는 `감염농장_전처리.ipynb`, `PROVINCE` 변수 하나만 바꾸면 같은 코드로 어떤 시/도든 처리한다.

### 데이터 구조

```
data/{시/도}/
  ├── 농장현황원본/   원본 가금류 농장현황 csv (파일명·컬럼명이 시/도마다 다름)
  ├── 감염농장원본/   원본 가축질병 발생정보 csv (시군별 1파일 또는 도 전체 1파일)
  ├── 농장현황/       파생: {시군}_농장현황.csv (표준 스키마로 정규화)
  └── 감염농장/       파생: {시군}_감염농장.csv

최종감염농장/{시/도}_최종감염농장.csv   ← 최종 결과 (12컬럼)
```

### 처리 방법

1. **인코딩 점검**: `data/` 전체 CSV가 UTF-8인지 확인, 깨졌으면 cp949/euc-kr에서 자동 복구
2. **농장현황 생성**: 날짜별 통합 파일(경기도)과 시군별 개별 파일(그 외 시/도)을 모두 지원. 농장명/사업장명/사업장명칭처럼 시/도마다 다른 컬럼명을 후보 목록 매칭으로 표준 스키마(시군명·농장명·축종명·상세구분·사육두수(마리)·소재지지번주소)로 정규화
3. **농장현황 중복 제거**: 시군명·농장명·상세구분·소재지지번주소·위도·경도·사육두수가 모두 같으면 중복
4. **감염농장 추출**: 원본에서 FARM_NM, FARM_LOCPLC, OCCRRNC_DE, LVSTCKSPC_CODE만 추출, FARM_LOCPLC 주소의 두 번째 토큰(시군명)으로 자동 분할
5. **감염농장 중복 제거**: 위 4개 컬럼이 모두 같으면 중복 (원본 API가 같은 사건을 다른 발생번호로 중복 등록한 경우가 있었음)
6. **주소 정확매칭**: FARM_NM == 농장명이면 FARM_LOCPLC를 농장현황의 소재지지번주소로 덮어씀 (동명 농장이 여러 건이면 조사날짜 최신 우선)
7. **최종 조인**: 정확매칭 → 실패하면 유사매칭 → 둘 다 실패하면 주소 기반으로 시군명/농장명만 보완. 시군구 전체를 합쳐 `{시/도}_최종감염농장.csv`(12컬럼) 생성

### 매칭 로직과 유사도 근거

매칭은 세 단계로 시도한다.

1. **정확매칭**: 감염농장의 `FARM_NM`과 농장현황의 `농장명`이 글자 그대로 같으면 매칭
2. **유사매칭**: 정확매칭이 안 되면, 주소 앞 4토큰(도/시군/읍면동/리)이 같은 후보들 중에서 이름 유사도(`difflib.SequenceMatcher`)가 **60% 이상**이면 매칭
3. **주소 기반 보완**: 둘 다 안 되면 FARM_LOCPLC의 두 번째 토큰을 시군명으로, FARM_NM을 농장명으로만 채우고 나머지(축종·상세구분·사육두수·좌표)는 비워둠

#### 왜 60%인가

정답 라벨이 없어서 정밀도·재현율을 직접 계산할 수는 없었다. 대신 경기도 데이터를 기준으로, 정확매칭에 실패한 건들에 대해 임계값을 올릴 때마다 추가로 몇 건이 매칭되는지를 비교했다.

| 임계값 | 추가 매칭 | 한 단계 아래 대비 손실 |
|---|---|---|
| 50% | 43건 | - |
| 60% | 32건 | -11건 (50~59% 구간) |
| 70% | 14건 | -18건 (60~69% 구간) |

- **50~59% 구간(11건)**: 이름이 짧을수록 음절 한두 개만 겹쳐도 50%를 넘기기 쉬워서, 실제로는 다른 농장인데 우연히 비슷해 보이는 오매칭 위험이 가장 큰 구간. 이 구간을 빼도 손실은 상대적으로 작다.
- **60~69% 구간**: "OO" ↔ "OO농장", "OO" ↔ "OO축산"처럼 흔한 접미사 표기 차이가 몰려있는 구간 (예: "서울" vs "서울농장" 유사도 약 67%). 실제로 같은 농장일 가능성이 높다.
- **70% 이상으로 올리면** 60~69% 구간 18건이 통째로 빠지는데, 다수가 흔한 접미사 변형이라 과도하게 엄격해진다.

즉 60%는 "오매칭 위험이 큰 50%대 구간은 제외하면서 흔한 표기 변형은 살리는" 절충점으로 선택했다. 라벨링된 정답으로 정밀도를 검증한 수치는 아니라는 한계가 있다.

### 예외 처리

원본 데이터가 시/도·시군마다 형식이 달라서, 아래 경우들을 코드에서 자동으로 흡수한다.

- **주소 컬럼이 2개로 나뉜 경우**
  - 지번주소/도로명주소가 별도 컬럼으로 둘 다 있는 경우(예: `사업장소재지(지번)`, `사업장소재지(도로명)`) → 지번주소를 우선 사용
  - 주소가 `소재지`+`상세소재지`처럼 두 컬럼으로 쪼개져 있는 경우 → 두 컬럼을 합쳐서 하나의 주소로 사용
- **따옴표 없는 콤마로 한 행이 깨진 경우**: 주소 안에 지번이 콤마로 여러 개 나열돼 있는데 따옴표로 안 감싸여 있어서(예: `고천리 316-3, 315-2`) 컬럼 수가 안 맞는 행이 있었음 → `csv.reader`로 직접 읽어서 넘치는 칸을 주소 컬럼 위치에서 `/`로 합쳐 복구 (행을 버리지 않음)
- **원본 값에 줄바꿈이 그대로 박혀있는 경우**: 일부 농장명 값 끝에 보이지 않는 줄바꿈 문자가 붙어있어서, 그대로 저장하면 엑셀 뷰어에서 셀이 깨져 보임 → 추출 단계에서 제거
- **컬럼명 자체가 시/도마다 다른 경우**: 농장명/사업장명/사업장명칭, 사육두수/사육수/사육수수처럼 같은 의미인데 표기가 다름 → 후보 목록 중 먼저 매칭되는 컬럼을 표준 컬럼으로 채택, 후보에 없는 컬럼명이거나 컬럼 자체가 없으면 빈 값으로 둠
- **행정구역 이름이 바뀐 경우**: 전라북도 → 전북특별자치도(2024년 개칭)처럼 옛 이름/새 이름이 주소·파일명에 섞여 나옴 → 별칭 목록(`PROVINCE_ALIASES`)으로 둘 다 인식
- **파일명 끝 날짜 자릿수가 다른 경우**: 보통 8자리(`20230814`)지만 6자리(연월만, `202102`)·4자리(연도만, `2022`)인 파일도 있음 → 자릿수에 맞춰 형식을 자동으로 선택
- **macOS 파일명 유니코드 정규화(NFD vs NFC)**: macOS는 한글 파일/폴더명을 분해형(NFD)으로 저장하는데 코드의 문자열은 결합형(NFC)이라 겉보기엔 같아도 비교가 실패함 → `unicodedata.normalize("NFC", ...)`로 정규화 후 비교
- **중복 다운로드 파일**: 같은 날짜인데 파일명 끝에 `(1)`이 붙은 파일이 있음(내용 동일 확인됨) → 자동으로 스킵

### 결과 (5개 시/도)

| 시/도 | 총 행 | 정확매칭 | 유사매칭(≥60%) | 매칭률 |
|---|---|---|---|---|
| 경기도 | 274 | 73 | 30 | 37.6% |
| 전라남도 | 248 | 48 | 19 | 27.0% |
| 전라북도 | 173 | 42 | 6 | 27.7% |
| 충청남도 | 123 | 34 | 16 | 40.7% |
| 충청북도 | 192 | 37 | 7 | 22.9% |

경기도는 추가로 농장현황 중복 제거에서 43,696건이 사전에 정리됐다 (조사시점별 중복 기록이 많았음).

### 알려진 한계

- 경기도는 가평군·과천시·광명시·군포시·시흥시·안산시·오산시·의왕시 8개 시군구에 원본 발생정보 csv가 없어서 감염농장 데이터 자체가 없다. 다른 시/도도 시군 커버리지가 들쭉날쭉하다.
- 매칭률이 22.9%~40.7%로 낮은 편이다. 농장명 표기 차이, 농장 폐업, 조사 시점 범위 밖 등으로 추정된다.
- 상세구분·WGS84 좌표는 경기도를 제외한 시/도 원본 데이터 자체에 없어서 항상 빈 값이다.
